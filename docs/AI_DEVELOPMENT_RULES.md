# AI開発運用ルール

## 1. 目的

AIの実装速度を活かしつつ、仕様の勝手な補完、広範囲改変、再現不能、テスト不足を防ぐ。

## 2. 役割

- 設計AI：仕様を小タスクへ分解。コードを大量実装しない。
- 実装AI：指定タスクだけ実装し、テストと全チェックを行う。
- レビューAI：別セッションで仕様準拠、不要変更、境界値、テスト不足を確認。

## 3. タスク粒度

1つの型、判定、集計、モジュール、CLI機能、不変条件テスト群のいずれかを基本とする。

## 4. Git

- 1タスク1ブランチ：`task/S00-001-workspace-foundation` 等。
- 既存の未コミット変更を破棄しない。
- コミットへタスクIDを含める。
- pushは明示指示がある場合のみ。

## 5. 実装前報告

```text
対象タスク:
参照資料:
変更予定ファイル:
実装方針:
対象外:
```

## 6. テスト

正常系、境界値、不正入力、再現性を対象タスクに応じて追加。実装詳細ではなく振る舞いを検証する。

Sprint 0の不変条件：年齢非負、死亡者非処理、16歳未満ランクなし、42歳以上引退、参照整合、親子・師弟循環なし、同一シード一致。

## 7. 設定・乱数

- 数値は設定オブジェクトへ集約。
- スキーマ検証を付ける。
- `Math.random()`禁止。
- RNGを依存注入。
- 設定ハッシュとシードを出力へ記録。

## 8. 仕様不足時

```text
不足している仕様:
実装への影響:
選択肢:
推奨案:
タスク停止が必要か:
```

独自判断で実装しない。

## 9. 完了チェック

対象テスト、全テスト、typecheck、lint、format check、build、差分確認。再現性対象タスクでは同一シード比較。

## 10. 完了報告

AGENTS.mdの固定形式を使用し、コード全文を貼らず変更点と結果を簡潔に報告する。
