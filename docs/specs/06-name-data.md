# 06 名前データ・選択ルールミニ仕様

- ミニ仕様バージョン：`S0-SPEC-0.1.4`

## 1. 目的

初期人物と家系へ、モチベーションを損なわない一般的な西洋ファンタジー風の名前を、生成AIを使わず再現可能に割り当てる。

## 2. データ構成

```text
data/names/
├─ name-data.manifest.json
├─ family-names.json
├─ male-given-names.json
├─ female-given-names.json
└─ neutral-given-names.json
```

基準データ `NAMES-0.1.2`：

- 家名：200件
- 男性名：400件
- 女性名：400件
- 共通名：100件
- 表示形式：`個人名・家名`

個人名と家名は別フィールドで保持し、表示名だけを保存元にしない。

## 3. manifest

`name-data.manifest.json` は次を保持する。

- スキーマバージョン
- 名前データバージョン
- ロケールと作風
- 表示形式
- 各候補ファイルの相対パス、件数、正規化JSONのSHA-256
- `hashAlgorithm=sha256-canonical-json-v1`
- 選択・重複回避ルール

候補ファイルの内容または配列順を変更した場合は、名前データバージョンを更新する。

## 4. 読込検証

- manifestと候補ファイルが存在する。
- 必須バージョンが設定値と一致する。
- 各候補JSONを02ミニ仕様と同じ規則で正規化し、そのSHA-256がmanifestと一致する。改行コード・字下げだけではハッシュを変えない。
- JSON内の `count` と配列件数が一致する。
- 同一ファイル内に重複・空文字・前後空白がない。
- 家名候補と3種の個人名候補の間に同一文字列がない。男性名・女性名間の重複は中性的な用例として許可する。
- 家名数が初期家系数以上である。
- 候補配列の順番をソートし直さない。

不整合時は名前を補完せず、初期世界生成を中止する。


## 5. nameDataHash

検証済み`name-data.manifest.json`を02ミニ仕様と同じ規則で正規化し、UTF-8バイト列のSHA-256を`nameDataHash`とする。候補配列・件数・候補ハッシュ・選択方針・名前データ版の変更はnameDataHashへ反映される。生ファイルの改行コードだけは結果へ影響させない。

## 6. 家名の選択

- 初期家系には家名候補を重複なしで割り当てる。
- Seeded RNGで候補配列を決定的にシャッフルし、家系ID順に割り当てる。
- 初期100家では200件中100件を使用する。
- 候補不足時に連番、接尾辞、再利用で補わずエラーとする。
- 家名と `familyId` は別データであり、家名変更後もIDを維持する。

## 7. 個人名の選択

1. 人物の性別に対応する候補を基本プールとする。
2. `neutralGivenNameProbability` の確率で共通名プールを選ぶ。
3. Seeded RNGで開始インデックスを1回決める。
4. 同時に存命する同一家系内に同一表示名がある場合、配列を循環して次の候補を決定的に走査する。乱数の再抽選は行わない。
5. 使用可能候補がない場合はエラーとし、乱数の再抽選を無制限に行わない。

- 世界全体で同じ個人名が存在することは許可する。
- 別家系の完全同名は許可する。
- 同一家系でも存命期間が重ならない祖先名の再使用は許可する。
- 同じ設定・シード・仕様版・名前データ版では、名前選択結果を完全一致させる。


## 8. 初期流派名

初期流派は専用の生成AIや機械連番を使わず、創始者の所属家名と主系統から決定する。

| 主系統 | 表示形式 |
|---|---|
| `unarmed` | `{創始家名}体術` |
| `sword` | `{創始家名}剣術` |
| `magic` | `{創始家名}魔術` |
| `mixed` | `{創始家名}総合術` |

初期24流派は異なる創始家系を使い、名称を重複させない。流派IDは名称と切り離して保持する。

## 9. 人物データ

最低限保持する：

```ts
interface PersonName {
  givenName: string;
  familyName: string;
  displayName: string;
  nameDataVersion: string;
}
```

- `displayName = givenName + "・" + familyName`。
- Sprint 0では改名、婚姻による姓変更、母系所属変更、家系再興による姓変更を処理しない。
- 後続Sprintで家系所属が変わる場合は、人物IDと個人名を維持して家名・表示名を更新できる構造にする。

## 10. 設定項目

`initial-world.config.json` の `nameData`：

- `manifestPath`
- `requiredVersion`
- `neutralGivenNameProbability`
- `familyNameSelection=without_replacement`
- `avoidDuplicateLivingFullNameWithinFamily=true`
- `displayFormat={givenName}・{familyName}`

確率は0〜1、manifestパスはリポジトリルートからの相対パスとする。

## 11. 受入テスト

1. 家名200、男性名400、女性名400、共通名100を読み込める。
2. manifestの件数・正規化JSON SHA-256とnameDataHashを検証できる。
3. 初期100家へ重複なしで家名を割り当てられる。
4. 同一シードで家名・個人名・表示名が一致する。
5. 異なるシードで少なくとも一部の名前が変わる。
6. 同時存命・同一家系の完全同名を回避する。
7. 別家系の同名を許可する。
8. 名前データの配列順変更時にバージョンまたはハッシュ差を検出する。
9. 実行時に生成AIや `Math.random()`を使用しない。
10. 家名と個人名候補の文字列が重複しない。
11. 初期24流派名が創始家名・主系統から一意に生成される。

## 12. 対象外

- 本番用の地域別・文化圏別命名
- 称号、通称、二つ名
- 改名・婚姻後の姓変更
- ユーザーが入力する始祖名の禁止語チェック
- 多言語表示
