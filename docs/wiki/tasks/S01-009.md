- 依存: S01-008 **implemented / accepted**（commit `7c47847`）
- 仕様版: `S1-SPEC-0.1.20`（S01-009 clarificationでは非bump）
- 実装状態: pending／未着手
- 正規完了検証入口: `npm run verify:sprint1`（S01-009で実装）
- verifierのscript／build／Node起動方式は既存`verify:sprint0`を踏襲し、`tsx`／`ts-node`等の新runner依存を追加しない
- 完了レポート: `output/sprint1-verification/sprint1-completion-report.json`、verification schema `0.1.0`
- verification-owned CLI run: `output/sprint1-verification/runs/<run-key>/`を既存`runCli(...,{outputRoot})`へ渡し、実fixed7は既存layoutの`<run-key>/<runId>/`に置く。runId階層をflattenしない。各run-key rootは開始前empty／nonexistent、成功後exactly 1 runId directory。`--output-root`等のpublic CLI optionは追加せず、一般の`output/`やユーザーrunをcleanupしない
- integrated scenarioのfixed7も同じrun-key／runId layoutで、accepted `buildAndWriteSprint1RunOutput`＋`evaluateReferenceIntegrity`を再利用する。verification専用flat writer／別integrity計算は禁止
- same-seed: base seed 12345、100年×2。run-metadataは`runId`／`realStartedAt`／`realEndedAt`のexact 3 fieldだけ除外してproduction canonical JSON比較
- different-seed: 12345 vs 54321。simulationIdだけでなく実体world差必須
- boundary seed: 0／4294967295、各1年×2run
- 年数profile: 10／50／100／300年
- performance: seed 12345固定、600／2000／5000人×100年。30秒／120秒warning、5000 measure only。600／2000超過warningは`SPRINT1_PERFORMANCE_WARNING`／`performance/<population>`。超過aloneでfailureにしない。5000もrequired profileで、functional成功時status=`passed`（`not_performed`ではない）。3profileは600→2000→5000の順に独立childを1つずつ順次実行し、並列計測しない
- performance sidecarはaccepted tiny `sprint1-input.json`のvalidated sidecar entriesでPersonId昇順先頭entryをtemplateとし、各generated PersonIdへ`personId`だけ置換。他field値を新規発明しない。factoryはverification-only
- integrated scenario: weekly→選択official participant自身の技状態更新event→更新済みPersonをBattleParticipantSourceへ反映→`official` completed battle（production `default_strategy`）→commit→次週reset→fixed7。weekly-training eventは`sourceProcessor=weekly-training`だけを対象とし、actorは`EventEnvelope.entities.personIds` exact 1件の唯一PersonIdを正本としてpayloadから人物を推測しない。weekly前後の`techniqueStates`実差も確認する。weekly stepはexact 2回、outputは`weeksExecuted=2`／`yearsExecuted=0`／`yearEnds=[]`、yearly CSV data row 0件。CLIへ自動battle scheduler／scripted結果固定を追加しない
- integrated battleではaccepted public helper（`isEligibleForBattleKind`／`validateBattleParticipantSource`／`computeExpectedWorldStateHash`／`computeMatchesCompletedThisWorldWeekBeforeBattle`／`validateBattlePostProcessContext`／`createDefaultStrategyActionSourceIdentity`／`validateDefaultBattleStrategySource`）を再利用し、hash・eligibility・same-week count・strategy採点をverification側で再実装しない。1 scenarioにつきbattle attemptは1回、completed以外をretryしない
- identity/canonical: sidecar単一値mutation・key-order不変・cross bindに加え、production `Math.random(...)` call expressionをAST／token-awareにscanし、comment／string文字列は誤検出しない
- command gates: `npm run check`、独立`npm run wiki:check`、`git diff --check HEAD`相当、`npm run verify:sprint0`を全て明示実行・reportへ保存
- Sprint 0回帰: `npm run verify:sprint0`を総合ゲートへ含める
- Sprint 0回帰は`npm run verify:sprint0`後、正規`output/sprint0-verification/sprint0-completion-report.json`だけを読む。warning正本fieldはaccepted reportの`warningCount`＋`performanceWarnings`。Sprint0 verification領域のaccepted report型／validatorを再利用してsource wire型を再定義せず、validated warning message件数との一致を検証する。各source warning messageをtop-level Sprint 1 `warnings`へ1件ずつimportし、Sprint 1 performance warningと合わせて`warningCount`へ反映。存在しないsource `warnings`配列を前提にしない。`verify:sprint1`自身の再帰呼出しは禁止
- verifier exit: 0=`overallPassed=true` report正常生成、1=functional／harness failure。集約可能なfailureでは`overallPassed=false` reportを必ずatomic writeし、report write/read-back自体のfailureだけreport不在exit 1を許す。stale report禁止・atomic write/read-back validation
- same-seed comparatorは05仕様準拠のverification-private helper。S01-008に存在しないproduction comparatorを前提にしない
- S01-009 accepted後、handoff artifact等をworktree外へ退避したclean masterで`verify:sprint1`を再実行し、終了後もcleanであることを確認してから`Sprint 1`完了tag `sprint1-complete`。official verifierはGit HEAD解決必須で、`verify:sprint1`自身はtag操作を行わない
- completion report SHA-256はatomic write／read-back後に外部計算し、reportへ自己hashを書かない。既存`sprint1-complete` tagのforce moveは禁止
- 受入条件・比較対象・fixture／performance sidecar生成境界は正本バックログの本タスク節を正とする
