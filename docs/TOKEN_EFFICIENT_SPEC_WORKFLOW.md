# トークン節約型の仕様・AI開発運用

## 原則

長い `docs/SPEC.md` を毎回全文読ませない。各タスクでは次だけを渡す。

1. `AGENTS.md`
2. `docs/TECHNICAL_DECISIONS.md`
3. 対象の `tasks/Sxx-xxx.md`
4. タスク指定の `docs/specs/*.md`
5. 必要な場合だけ `docs/SPEC.md` の該当見出し

## 4層

| 層 | ファイル |
|---|---|
| 企画正本 | `docs/SPEC.md` |
| 技術決定 | `docs/TECHNICAL_DECISIONS.md` |
| ミニ仕様 | `docs/specs/*.md` |
| 作業指示 | `tasks/*.md` |

## 先に仕様化するもの

入力、出力、処理順、状態遷移、設定キー、不変条件、イベント、エラー、対象外、受入テスト。

確率・係数・人数上限・大会回数・出生率・成長速度などは設定へ分離し、実測後に調整する。

## 実装AIの短い依頼形式

```text
AGENTS.md、TECHNICAL_DECISIONS.md、対象タスク、指定ミニ仕様だけを確認してください。
対象外を変更せず、実装・テスト・全チェック・完了報告まで実行してください。
矛盾があれば独自補完せず停止してください。
```

## レビューAIへ渡すもの

AGENTS、対象タスク、対象ミニ仕様、Git差分、テスト結果だけ。実装AIとは別セッションでレビューする。

## 仕様変更

不足を発見 → 実装停止 → 仕様側で決定 → SPEC・変更履歴・ミニ仕様更新 → 新しいタスクで再開。
