# S00-002 共通型と設定スキーマ

## 目的

00・02・06ミニ仕様に基づき、ID、人物状態、設定型、JSON読込・検証・正規化・ハッシュ契約を実装する。

## 参照資料

- `AGENTS.md`
- `docs/TECHNICAL_DECISIONS.md`
- `docs/specs/00-domain-glossary.md`
- `docs/specs/02-config-schema.md`
- `docs/specs/06-name-data.md`

## 前提

S00-001完了。

## 実装範囲

- 00ミニ仕様のID、存命／死亡人物union、性別、能力キー、適性キー、ランク、関係型
- 02ミニ仕様の未知キー拒否を含む設定読込・明示的検証
- canonical JSONの生成
- `Sha256Provider`インターフェースと、注入されたproviderによる`configHash`／`nameDataHash`算出
- 06ミニ仕様のmanifest・候補ファイル型と読込検証用の純粋処理

## 変更可能範囲

- `packages/simulation-core/**`
- このタスクで追加するテストファイル

## 対象外

- 初期世界生成
- Seeded RNG実装
- `node:crypto`の具象実装
- CLI、ファイルI/O、MySQL、ORM

## 入力

- `config/initial-world.config.json`と名前データはテストfixtureまたは読込済み値として扱い、リポジトリ内の原本を変更しない。

## 出力

- 公開型、検証結果、canonical JSON、ハッシュprovider契約。

## 受入条件

- 00・02・06ミニ仕様の対象受入条件を満たす。
- 未知キー、範囲外値、件数不整合を明示的に拒否する。
- `simulation-core`が`node:crypto`や外部実行時依存を直接参照しない。
- `npm run check`が成功する。

## 必須テスト

- 存命／死亡人物unionと固定キーの型テスト
- 設定の正常系・未知キー・境界値・件数整合性
- canonical JSONがキー順・空白・改行に左右されないこと
- 注入したstub providerで`configHash`／`nameDataHash`の材料が一致すること

## 必須コマンド

```text
npm run check
```

## 完了報告

`AGENTS.md`の完了報告形式を使用する。仕様との差異・未解決事項がない場合も「なし」と明記する。
