# S00-005 構造化イベント基盤

## 目的

03ミニ仕様のEventEnvelope、決定的eventId、sequence、JSONL正規化を実装する。

## 参照資料

- `AGENTS.md`
- `docs/TECHNICAL_DECISIONS.md`
- `docs/specs/00-domain-glossary.md`
- `docs/specs/03-event-envelope.md`

## 前提

S00-002、S00-004完了。

## 実装範囲

- `EventEnvelope`型
- 0始まり`sequence`と`sequence+1`から作る`eventId`
- 初期イベント・週次イベントfactory
- 決定的JSONL文字列化
- sequence欠番・重複・参照整合性の検証
- `WorldCalendarTransition`の`person_debuted`を`person.debuted`へ変換する
- `person.debuted`のpayloadへ付与ランクと前後`careerStatus`を保存する
- `person.career_status_changed`とは別イベントとして順番を維持する

## 変更可能範囲

- `packages/simulation-core/**`
- このタスクで追加するテストファイル

## 対象外

- ニュース文章生成
- ファイル書込
- MySQL
- 戦闘詳細ログ

## 入力

- simulationId、世界日時、sequence、event種別、参照ID、payload。

## 出力

- 決定的なEventEnvelope配列とJSONL文字列。

## 受入条件

- 初期世界で世界1年の`world.year_started`を生成しない。
- sequence 0のeventIdが`event_000000001`となる。
- 同じイベント列は同じJSONLになる。
- 欠番・重複・壊れた参照を検出する。
- `person.debuted`は`person.career_status_changed`と別イベントとして順序を保つ。
- `npm run check`が成功する。

## 必須テスト

- 03ミニ仕様の全受入テストを実装する。
- `person_debuted`から`person.debuted`への変換で、付与ランクと前後`careerStatus`が保存される。
- `person.career_status_changed`と`person.debuted`が別イベントとして順番を維持する。
- 同じ入力から同じsequence、eventId、JSONLになる。

## 必須コマンド

```text
npm run check
```

## 完了報告

`AGENTS.md`の完了報告形式を使用する。仕様との差異・未解決事項がない場合も「なし」と明記する。
