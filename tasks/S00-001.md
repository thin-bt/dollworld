# S00-001 npm workspaces・TypeScript品質基盤

## 目的

後続タスクが同じ品質条件で実装できる、最小のnpm workspaces／TypeScript基盤を作る。

## 参照資料

- `AGENTS.md`
- `docs/TECHNICAL_DECISIONS.md`
- `docs/SPEC.md` の「Webアプリの技術構成」「推奨リポジトリ構成」

## 前提

ゲームロジックはまだ存在しない。既存のdocs、config、data、tasks、promptsを保持する。

## 実装範囲

- ルートnpm workspaces：`packages/*`、`apps/*`
- Node `>=24.18.0 <25`／npm `>=11.16.0 <12`のengine指定と`packageManager: npm@11.16.0`
- ルートpackage名`shared-world-observation-game`、workspace package名`@shared-world/simulation-core`
- root／workspaceとも`private: true`
- ESM
- ルート品質ツールと固定バージョン
- `tsconfig.base.json`
- ESLint flat config
- Prettier設定と、既存資料を対象外にする`.prettierignore`
- `.gitignore`、`.gitattributes`、`.nvmrc`
- `packages/simulation-core` の最小package（package名`@shared-world/simulation-core`）
- 最小exportとsmoke test
- root scripts：`build`、`typecheck`、`lint`、`format`、`format:check`、`test`、`check`
- `package-lock.json`（初回は`npm install --package-lock-only --ignore-scripts`で生成後、`npm ci`を実行）

## 変更可能範囲

- ルートの開発設定ファイル
- `packages/simulation-core/**`
- `package.json`、`package-lock.json`

## 対象外

- ドメイン型、世界暦、RNG、設定スキーマ、CLI
- React、Vite、Fastify
- MySQL、ORM
- docs、config、dataの内容変更
- ゲーム仕様変更

## 入力

- 現在のスターター一式。ゲームデータや外部サービスからの入力は使用しない。
- `docs/TECHNICAL_DECISIONS.md`に固定したNode.js・npm・開発依存バージョン。

## 出力

- npm workspaces対応のルート開発設定。
- `packages/simulation-core`の最小ESM／TypeScript packageとsmoke test。
- npmが生成した`package-lock.json`。

## 受入条件

1. 公開済みの固定依存だけでlockfileを生成でき、続けて`npm ci`が成功。
2. `npm run check` が成功。
3. TypeScript strictが有効。
4. simulation-coreがReact、HTTP、DBへ依存しない。
5. smoke testが1件以上成功。
6. ESMとしてbuildできる。
7. package-lockが存在し、package.jsonとの不一致がない。
8. 既存資料が削除・改変されておらず、`.gitattributes`でLFが固定されている。
9. `npm run check`が`format:check → lint → typecheck → test → build`を実行する。

## 必須テスト

- simulation-coreの公開exportをimportできる。
- テストランナーがCIモードで終了する。

## 必須コマンド

```text
node --version
npm --version
npm install --package-lock-only --ignore-scripts
npm ci
npm run check
```

## 完了報告

AGENTS.mdの形式を使用する。依存バージョンと全コマンド結果を明記する。
